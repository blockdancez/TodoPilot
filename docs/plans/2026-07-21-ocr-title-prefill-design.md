# OCR 任务标题预填设计

## 目标

在 `free` 分支的本地 OCR 建任务流程中，完整识别文本继续预填到任务内容，同时自动预填一个可编辑标题。界面布局、样式、优先级和截止时间默认值保持不变。

## 方案比较

1. 取第一条非空行并截断：规则稳定、完全本地、不会把后续 OCR 噪声塞进标题。采用此方案。
2. 截断全部 OCR 文本：实现简单，但多行文本会生成难读标题。
3. 按标点提取首句：看似自然，但文件名、版本号和 OCR 标点误识别会导致错误截断。

## 数据流

框选截图经过 Apple Vision 本地 OCR 和用户校对后，生成本地任务草稿：

- `detail`：保留用户确认后的完整文本。
- `title`：取第一条去除首尾空白后不为空的行，将行内连续空白合并为单个空格，再按 Swift 字符截断至 80 字。
- 没有有效文本时返回空标题；现有保存按钮校验继续阻止空标题入库。

标题和内容都只作为可编辑候选值，用户保存后才进入 Today List。

## 代码边界

- 新增无副作用的本地标题提取规则，便于单元测试。
- `TaskEditorSheet` 增加可选的初始标题参数；普通手动新建和编辑任务行为不变。
- OCR 浮动确认流程同时传入初始标题与完整内容。
- 不新增网络请求、AI 结构化、日志或遥测正文。

## 验证

- 覆盖单行、多行空白、行内连续空白、80 字截断、Emoji/组合字符和空文本。
- 运行 macOS 客户端完整测试，确认既有 UI 布局回归测试继续通过。
